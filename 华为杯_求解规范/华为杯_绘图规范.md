# 华为杯绘图规范

本文件是本项目绘图与可视化规则的唯一详细事实来源。它适用于 Codex、Claude Code 以及任何为华为杯论文生成、修改、审查或解释 Figure 的自动化流程。项目总控文件只负责触发本文件和定义门禁；求解规范只保留 Figure Plan、结果追溯、计算/绘图分离和质量门禁；论文规范只处理 LaTeX 接入与版面可读性。`求解/求解计划.md` 保存人类可读的证据与图件叙事，`求解/视觉计划.json` 保存同一计划的机器可审计字段；两者的 ID、数据源、输出、标签和状态必须一致。

## 1. 适用范围与触发条件

在以下任一动作前，必须先完整读取本文件：

- 创建、选择、修改、审查或解释任何 Figure、Table、可视化或图形代码；
- 在 `求解/求解计划.md` 或 `求解/视觉计划.json` 中编写或更新 Figure Plan、Schematic Plan；
- 在 `求解/求解计划.md` 中编写或更新 Flowchart Plan；
- 生成 `求解/问题X/图片/` 中的正式图片；
- 将图片、TikZ 图或图表引用写入论文；
- 处理三维图、多面板图、渐变、透明度、柱状图、饼图、SCI 风格图或流程图。

触发后必须按以下顺序执行：

1. 阅读本规范和题面约束；
2. 在 Evidence Matrix、Figure Plan、Schematic Plan 或 Flowchart Plan 中定义科学问题、真实来源、视觉编码和输出；
3. 运行计算并把结构化结果落盘；
4. 绘图脚本只读取已经落盘的结果，不重新训练、优化或猜测数字；
5. 渲染、审查、记录质量状态；
6. 只有通过质量门禁的图才能进入论文。

### 1.1 中文显示、字体检测与反乱码门禁

普通科学结果图的可见标题、坐标轴、图例、Panel 描述、注释、图内统计
解释和图注默认使用中文；原始数据字段、源文件和计算代码不因显示适配而
改写。应先 Copy-First 复制生产脚本，再只在渲染层映射标签或数据路径，并
在 Figure Plan 记录映射。

- Python 图必须通过项目内 `academic-figure-skill/scripts/chinese_fonts.py`
  检测实际安装且覆盖所需字符的字体，必要位置使用 `FontProperties`，并
  设置 `axes.unicode_minus=False`；
- R 图必须用 `systemfonts` 或等价机制检测字体，并用 Cairo 设备渲染 PNG/PDF；
- 必须执行 `fig.canvas.draw()` 或等价渲染调用。字体烟雾测试覆盖中文、单位、
  RMSE、负值、希腊字母和上下标，并检查 PNG/PDF 的缺字、重叠、裁切、缩放
  和灰度可读性；
- 缺少字体、检测不到字符、渲染警告或视觉检查失败时，Figure 状态为“未完成”，
  不得进入正式图片目录或论文；
- 流程图、模型结构图和总体技术路线图仍遵守 Flowchart Plan + TikZ/XeLaTeX
  门禁，不由该普通结果图适配层替代。

## 2. BrightTech-Info 可选视觉偏好与语义 token

**BrightTech-Info** 是华为杯项目的可选视觉偏好和语义 token 参考，不是所有 Figure 的强制模板。普通科学结果图优先服从 `academic-figure-skill` 对数据语义、期刊尺寸、字体、色盲友好和灰度可读性的判断；只有在不冲突且确实有助于表达时，才采用 BrightTech-Info 的高亮度、多色、适度半透明或轻量科技感。这里的“色彩丰富”指同一论文在不同数据语义间形成稳定而有层次的蓝、青、紫、绿、橙等视觉词汇，以及连续量使用合适的顺序/发散色图；单个 Figure 仍以 2--4 个语义主色加 1 个强调色为基线。不得为了保持某种品牌外观而改变图型、增加装饰或牺牲可读性。

### 2.1 基础画布与几何

- 优先白色或极浅灰背景；不使用大面积深色背景，除非题面或 skill 的数据语义明确要求。
- 辅助网格使用浅灰、低对比度线；非必要外框弱化或删除。
- 线条、节点、点和标注保持清晰，不使用夸张发光、厚重阴影、纹理背景或装饰性 3D。
- 论文缩放后仍须能读取中文、负号、希腊字母、上下标、单位和图例。
- 总标题由 LaTeX `\caption{}` 承担；图内只保留必要的 Panel 编号、轴标题、单位和关键注释。

### 2.2 颜色、渐变和透明度

- 颜色必须服务于数据语义。Baseline、Main Model、Competitive Model、Best Solution、区域、类别和连续变量在全文中保持一致。
- 连续变量允许使用有明确数值顺序的多色渐变；优先感知均匀、色盲友好、灰度仍有层次的色图。禁止无语义地使用彩虹色制造伪层次。
- 分类变量使用稳定且可区分的离散色板；可优先从蓝、青、紫、绿、橙等颜色中选择，但具体色值由 skill 按数据语义、色盲友好和灰度可读性决定，类别顺序改变时不得重新随机分配颜色。
- 半透明只用于置信区间、不确定性带、密度层、重叠区域或背景辅助层。核心曲线、边界、文字、坐标轴和图例保持较高不透明度。
- 透明度不能遮蔽数值、改变面积/密度判断或造成重叠区域无法区分；同一语义层在不同 Panel 使用相同 alpha。
- 颜色不能成为唯一编码。关键比较还应使用线型、marker、位置、边界或文字，保证灰度打印可辨。

## 3. 视觉编码表与颜色语义

每个真实项目必须在 `求解/视觉编码表.md` 固化实际采用的语义 token、色值、线型和 marker。下表只规定抽象语义，不强制固定 HEX；具体色值由 `academic-figure-skill` 根据当前 Figure 的数据结构和输出尺寸决定，并在项目表中固定复用。

| Token | 抽象语义 | 推荐线型/marker |
|---|---|---|
| Baseline | 基线、原始方案或对照 | `--`, `o` |
| Main Model | 主模型、最终采用方法 | `-`, `o` |
| Competitive Model | 竞争方法或替代模型 | `-.`, `s` |
| Best Solution | 最优解、关键方案或被强调结果 | `-`, `*` |
| Continuous Gradient | 连续量、响应面、密度或热力层 | colorbar |
| Uncertainty Band | 置信区间、预测区间或不确定性 | alpha 由数据可读性决定 |
| Highlight | 阈值、峰值、交叉点或关键事件 | `:`, `D` |
| Neutral Auxiliary | 辅助线、背景参考、不可比较的注释 | `:`, `x` |

需要额外类别色时，可登记抽象的 `Category Green`（具体色值由 skill 选择并写入项目视觉编码表），并在全文固定复用；不得临时改色。

要求：

- `Baseline`、`Main Model`、`Competitive Model` 和 `Best Solution` 在所有 Figure 中复用同一语义；
- colorbar 必须写明变量、单位和方向，且共享量纲的 Panel 共享范围；
- 灰度备份至少给出线型/marker/明度对应关系；
- 不为了“颜色丰富”给无数据含义的元素换色；
- 颜色选择与题面官方色彩要求冲突时，题面优先，并在编码表记录例外。

## 4. 图型选择矩阵

图型由科学问题、数据结构和可读性决定，不存在默认图型。Figure Plan 必须写明为什么选择该图型以及为什么没有选择更简单的替代图。

### 4.1 趋势与变化

- 适用：时间序列、迭代过程、参数扫描、预测轨迹和变化率。
- 推荐：折线图、时间序列图、变化率图、预测曲线、置信带。
- 数据：有序连续轴和同一指标的多组观测/预测。
- 布局：共享 x 轴的 1×2 或 1×3；主曲线与残差/区间可组合。
- 不适用：类别没有自然顺序或每组只有一个独立数值。
- 单独出现：当趋势本身就是结论时可以；否则与误差或分布 Panel 组合。

### 4.2 方法比较与排序

- 适用：Baseline、Main Model、Competitive Model 的指标或排名比较。
- 推荐：排序点图、误差线图、箱线图、小提琴图、水平条形图；柱状图仅在类别少且长度比较确实必要时使用。
- 数据：模型×指标、重复实验或交叉验证结果。
- 布局：按指标分面或 1×2（性能/误差），共享零线和尺度。
- 不适用：类别很多、尺度差异大或需要展示完整分布时的单色柱图。
- 单独出现：精确比较可单独出现，但优先配合不确定性或排序信息。

### 4.3 预测与回归验证

- 适用：预测可靠性、残差结构和校准。
- 推荐：实际值–预测值散点、残差图、残差分布、预测区间、校准曲线、Q-Q 图。
- 数据：观测值、预测值、残差、分组或时间索引。
- 布局：2×2（预测对比、残差、分布、校准）或 1×2（主对比/残差）。
- 不适用：只展示单一相关系数而不展示误差结构。
- 单独出现：实际–预测图可作为主证据；其它诊断通常与它组成 Panel。

### 4.4 分类与聚类

- 适用：类别判别、阈值选择、嵌入结构和聚类质量。
- 推荐：混淆矩阵、ROC、PR、PCA/UMAP 散点、聚类分布、Silhouette 图。
- 数据：标签、概率、嵌入坐标、距离或聚类编号。
- 布局：2×2 或 1×3，类别颜色与全篇编码表一致。
- 不适用：类别极不平衡时只给 accuracy 柱图。
- 单独出现：混淆矩阵或 ROC 可单独出现，但应在正文解释基准率和阈值。

### 4.5 优化与决策

- 适用：收敛、权衡、敏感性、资源分配和调度。
- 推荐：目标函数收敛曲线、Pareto 前沿、参数敏感性热力图、资源分配图、Gantt 图、优化前后对比。
- 数据：迭代历史、可行解、目标向量、参数扰动、任务时段和资源量。
- 布局：收敛/可行性 1×2；Pareto/敏感性可 1×2 或 2×2。
- 不适用：用装饰性曲线代替约束可行性或目标定义。
- 单独出现：Pareto 或收敛图可作为核心图；资源图需在题面确有调度/分配含义时使用。

### 4.6 分布、不确定性与稳健性

- 适用：误差、重复试验、bootstrap、扰动和鲁棒区间。
- 推荐：箱线图、小提琴图、KDE、ECDF、bootstrap 分布、灵敏度图、鲁棒区间图。
- 数据：重复样本、模拟结果、扰动场景和分位数。
- 布局：同一指标按方案分面，共享 y 轴；不确定性带与主趋势共享色义。
- 不适用：只用均值柱图隐藏分布和异常值。
- 单独出现：分布图可单独出现；KDE 需在样本量足够且带宽合理时使用。

### 4.7 关系与相关性

- 适用：变量关系、回归结构、相关性和密度。
- 推荐：散点图、回归关系图、hexbin、相关矩阵、散点矩阵。
- 数据：成对观测、分组、密度或相关系数。
- 布局：散点+边际分布或相关矩阵；第三变量最多再加入一种视觉通道。
- 不适用：同时用颜色、大小、形状、透明度和分面编码过多维度。
- 单独出现：关键关系可单独出现；相关矩阵需配合显著性或变量筛选解释。

### 4.8 空间、结构与流程

- 适用：空间分布、等值线、网络、数据流和图像叠加。
- 推荐：空间分布图、等高线、网络拓扑、Sankey、流程图、图像分割叠加、结构图。
- 数据：坐标、几何对象、边/节点、流量或真实图像。
- 布局：主空间图配局部放大、剖面或误差 Panel；流程图保持真实数据流方向。
- 不适用：没有空间或拓扑含义的装饰性地图/网络。
- 单独出现：流程图可单独出现但必须支撑模型结构；Sankey 必须有守恒或流量语义。

## 5. 三维图使用要求

三维图没有硬性数量目标，也不是论文页数或图数的填充项。只有题面和真实结果中存在可解释的三变量关系、响应面、空间结构、三维轨迹、点云、几何对象、时空关系或优化前沿时，才选择三维表达；每一张图都必须回答明确的科学问题并通过独立质量检查。

允许的三维含义包括：三变量关系、参数响应面、空间结构、优化前沿、三维轨迹、点云、几何对象或时空关系。优先使用三维散点、曲面、响应面、曲面+等高线、三维 Pareto 前沿、空间分布、轨迹和误差分布。

每张三维图必须在 Figure Plan 中记录：x/y/z 的变量、单位、坐标范围、视角选择、颜色或 colorbar 含义、遮挡处理、对应的二维投影/等高线/热力图或侧面 Panel，以及它支撑的定量结论。

三维图不得使用三维饼图、装饰性三维柱状图、没有数据含义的立体坐标、过度透视或过度透明。三维图必须同步给出可核验的参数、连通关系、不确定性或误差指标，不能只凭透视效果判断结论。

若题目不存在真实且可解释的三维关系：不得伪造三维数据；改用二维等高线、热力图、散点矩阵、二维投影、误差图或多面板 Figure，并在 Figure Plan 记录替代原因。即使只有一个真实三维关系，也不应为凑数量制造第二张三维图。

## 6. 柱状图、饼图及相关限制

柱状图不是默认图型。只有类别少、数值长度比较是核心问题，且排序点图、误差线图、箱线图或热力图不能同等清楚表达时才使用。类别较多时优先水平条形图；必须说明颜色的类别语义；不得使用装饰性三维柱状图或大量无意义单色柱图。

饼图不是默认图型，也不能单独作为核心证据。仅在少量（原则上不超过 4–5 个）互斥类别的整体构成是科学问题时使用，并优先作为多面板 Figure 的一个 Panel，与趋势、排序、堆叠图、热力图、流程图或其它诊断组合。能用排序点图、堆叠图或面积图清楚表达时放弃饼图。禁止三维饼图、爆炸效果、厚重阴影和装饰性渐变。

## 7. 多面板 Figure 与布局

- 一个 Figure 围绕一个科学问题；不同科学问题不得为了凑图数硬拼。
- `quantitative_grid` 只在 Panel 科学权重相当时使用对称布局；`schematic_led`、`image_plate_quant` 和 `asymmetric_mixed` 在 3--6 个 Panel 时必须指定 hero panel，使核心证据面积约为支持 Panel 的 1.2--1.5 倍。
- 1×2 适合二元比较或主结果/残差；1×3 适合三个互补维度；2×2 适合四种诊断；2×3 适合六个同构对象。非规则布局、局部放大和 inset 只能由真实信息结构驱动。
- Panel 之间保持与科学问题相符的语义一致性（单位、共享轴/色标和必要的视觉 token）；字体、字号、线宽、marker、alpha、布局细节和图例摆放由 `academic-figure-skill` 按目标尺寸决定，除非题面另有硬约束。
- 子图编号统一为 `(a)`、`(b)`、`(c)`，放在不遮挡数据的位置；总标题由 `\caption{}` 给出。
- 共享 legend、colorbar 和轴标签优先；重复图例和重复刻度应合并或删减。
- 先增大 Figure、调整布局、减少标注、调整图例和稀疏刻度，再考虑小幅缩小字号；最终字号、线宽和尺寸遵循 `academic-figure-skill` 的期刊规格与可读性 QA，项目不设跨 Figure 的固定字号或线宽。
- 不用大量逐点标注、拥挤文本或空白分页来制造页数。

### 7.1 视觉证据覆盖与组合门禁

Figure Plan 必须在编写本问求解代码前完成第一版，并反向声明每个 Panel 所需的结果文件、字段、扫描范围、重复次数、统计量和单位。求解程序据此真实计算并落盘；不能在绘图脚本中临时制造扫描、重复试验或示例数字。

每个问题的 Evidence Matrix 至少审查以下四类视觉证据，并为每一行填写 `figure / schematic / table / text / N/A`：

1. 机理、几何、坐标、数据流或算法结构；
2. 主结果和题目要求的关键输出；
3. 独立验证、误差、守恒量、约束或理论边界；
4. 敏感性、鲁棒性、场景、收敛或反事实。

多点扫描、重复试验、分布、误差结构、矩阵/响应面和空间几何默认优先使用 Figure；若改用 Table/Text，必须记录为什么图形不能增加可验证信息。每个问题至少有主结果图；标准或复杂问题还必须有独立验证图。简单问题通常至少 2 个 Figure，标准或复杂问题通常 3--6 个；低于审查阈值时必须提供具体的不适用理由和替代证据，并由 `tools/audit_visual_plan.py` 拦截或告警。图数不是评分目标，任何新增图仍须有独立科学问题和真实结果源。

对常见四问型赛题，组合规划目标通常为总体/机理 1--3 个、每个标准或复杂问题 3--6 个、全局敏感性/综合验证 1--2 个，合计约 15--25 个非冗余 Figure；这只是组合级审查带，不是硬凑数指标。若已有 4 个以上 Figure，不能全部机械使用同一种布局；若已有 6 个以上 Figure，必须审查是否至少使用两种与数据相符的 archetype。图型多样性来自问题和数据，不得把同一结果改画成不同图型凑多样性。

### 7.2 正文证据密度与补页图门禁

视觉计划除检查图数，还要检查图在正文中的分布。模型/机理、主结果、验证、误差、敏感性与边界图应尽量靠近对应问题，不能把图全部集中在前半段，再以全量折表、文件审计或交付说明撑后半段。论文初稿生成后制作逐页联系表；若正文后 1/3 连续出现低信息密度页，优先把真实的设备/场景差异、逐折不确定性、参数可辨识性、残差分层、模型胜负、特征响应或边界证据前移并图形化。

页数不足时，允许新增“解释性证据图”，但必须同时满足：

1. 回答正文尚未可视化的具体科学问题；
2. 只读取已落盘的真实结果，或由新增计算脚本真实生成并登记结果；
3. 与已有 Figure 不同证据、不仅是同一数据换图型；
4. 具有可复核的统计/边界/分组/不确定性含义；
5. 通过 Figure Contract、统计报告、字体和渲染 QA。

适合的补充族包括：参数目标面与 bootstrap 联图、折级森林图/胜负热图、设备×验证口径误差谱、残差随状态/时间分层、特征局部响应、阈值/可行域、模型失效地图和带置信区间的敏感性图。装饰性流程图、无数据三维图、同一数字的饼图/柱图重复、虚构示例曲线以及仅为占版面的“好看图”一律不合格。若题目证据不足以支持更多图，应承认不适用并调整章节，而不是制造视觉填充。

### 7.3 Schematic Plan：机理/几何示意图

Schematic Plan 专门管理不表达计算顺序的数据机理与几何示意，例如轨道/空间几何、坐标旋转、传播路径、相对论几何、采样、分箱、折叠原理和物理作用关系。它与 Flowchart Plan 的边界如下：

- 主要回答“对象、几何或机理如何构成”，没有算法顺序、决策分支或数据流的，使用 Schematic Plan；
- 主要回答“输入如何经过步骤/模型到达输出”，或包含迭代、反馈、验证门、分支的，使用 Flowchart Plan；
- 同一 Figure 同时含机理示意和定量 Panel 时，可使用 `schematic_led` archetype，但示意 Panel 仍必须先通过 Schematic Plan + TikZ/XeLaTeX，定量 Panel 仍通过 `academic-figure-skill`；不得用 skill 自动生成的装饰性 schematic 绕过真实性审查。

每个 Schematic Plan 至少记录：Schematic ID、科学问题、类型、题面/公式/代码/结果来源、真实元素及其关系、可删除元素、TikZ 源、PDF/PNG、图题、label、正文引用、字体/灰度/版心/裁切状态。示意图必须使用 TikZ/XeLaTeX 矢量输出；任何元素或关系无法追溯时状态为“未完成”。

## 8. Python、R 与 TikZ 实现要求

### 8.1 Python / matplotlib / seaborn

- Python 是默认绘图工具；matplotlib 负责底层可控渲染，seaborn 仅作为统计图辅助，不能覆盖项目视觉编码表。
- 正式绘图前检测实际中文字体并执行中文、负号、希腊字母和单位烟雾测试；无可用中文字体时停止，不得用默认字体静默输出乱码。
- 每个 Figure 使用独立绘图函数；计算脚本和绘图脚本分离；绘图脚本只读 `求解/问题X/结果/`。
- 保存前执行 `fig.canvas.draw()`，捕获字体缺失、布局失败和 colorbar 异常；不得用全局 `warnings.filterwarnings('ignore')` 隐藏这些问题。
- 优先 `constrained_layout=True` 或经验证的 `tight_layout()`，不可无脑叠加两套布局系统。保存后核验文件存在、非空、像素尺寸、DPI、边界和裁切。

### 8.2 R

- R 仅在统计建模或 ggplot2 表达明显更合适时使用；先用 systemfonts 检测中文字体。
- `theme_set`、色板、线型和透明度必须与视觉编码表一致；设备渲染失败时退回 Python，不得输出乱码图。
- 使用 patchwork/cowplot 等多面板工具时，Panel 仍须共同回答同一科学问题并共享编码。

### 8.3 TeX Live / TikZ

- 流程图、模型结构图和论文内矢量示意图使用 XeLaTeX + TikZ，禁止截图和软件水印。
- TikZ 节点使用论文正文中文字体体系，不硬编码本机不存在的字体；编译日志检查 `Missing character`、`fontspec Error` 和字体缺失。
- 节点、箭头、分组、颜色和线型必须来自本文件的语义规则与真实模型结构；不得在论文规范中另建 A/B/C 固定视觉模板。
- TikZ 图也必须有 Figure Plan；机理/几何示意图还必须有 Schematic Plan，流程图/模型结构图还必须有 Flowchart Plan；所有图均须有结果或模型来源、`\caption{}`、唯一 `\label{}` 和正文 `\ref{}` 引用。

## 9. 流程图与模型结构图规范

流程图、总体技术路线图、模型结构图、算法流程图和数据流/模块关系图都属于结构性 Figure。它们不是装饰图，也不是用于增加论文页数的版面填充。只有当图能够增强以下至少一项的表达时才生成：全文技术路线、多问题依赖、输入—模型—输出—验证关系、多层模型结构、算法步骤与迭代、优化/预测/验证反馈闭环、数据/结果/决策流，或系统架构与模块关系。若正文文字和公式已经清楚表达且流程图不会增加可验证信息，应在 Figure Plan 中记录“不需要流程图”，不得强行生成。

### 9.1 结构类型选择

结构类型只能由真实题面、数据流和模型结构决定，不得固定套用某一模板，也不得把历史 A/B/C 代码块当成生产模板。可选类型如下：

1. **总体技术路线图**：展示全篇或多个问题的输入、处理、核心模型/算法、输出、独立验证和总体结论；存在多问依赖时按真实问题分行或分组，列数、行数和节点数随题目调整。
2. **分层系统架构图**：仅在数据、特征/状态、模型/算法、约束/校验、结果/决策确有层级或耦合关系时使用；右侧全局验证区只有在存在真实全局校验时才保留。
3. **纵向算法流程图**：用于有真实初始化、计算/更新、收敛或停止判断、输出的顺序算法；循环或反馈箭头必须对应代码、公式或明确停止条件。
4. **双阶段或多阶段协同流程图**：用于粗解—精解、Baseline—改进、预测—优化、候选生成—筛选—Pareto 权衡或多阶段场景；必须标出阶段之间传递的真实变量、目标向量、可行域或风险指标。
5. **输入—模型—输出—验证图**：用于多个数据源进入不同模型、各模型有独立输出和验证指标、最后再汇总的结构；行列按实际问题和功能调整。
6. **数据流或模块关系图**：用于复杂数据处理、网络/图结构或具有真实依赖的系统组件；每个分组框、模块框和验证节点都必须能追溯到题面、代码、公式或结果。

### 9.2 节点、箭头和真实性

- 在绘图前先回答：图要解释的科学问题、图型、输入、中间模型/计算、输出、验证条件、循环/分支、每个节点来源、每条箭头传递的信息、可删除节点以及是否应拆图。
- 每个节点必须对应真实存在的题面数据、处理步骤、特征/变量、数学模型、算法、参数、约束、中间结果、输出结果、验证指标、决策或场景。节点文字使用具体名称，优先写“清洗后的时序数据”“特征矩阵”“参数估计值”“候选解集合”“可行解”“预测结果”“残差指标”“Pareto 解集”“独立验证结果”等；避免“信息输入”“数据处理”“模型计算”“结果输出”“信息传递”等空泛标签。
- 每条箭头必须对应真实的数据/变量传递、模型依赖、计算顺序、约束关系、反馈关系或验证关系；箭头方向与实际数据流和求解顺序一致，箭头文字写明传递的变量或关系。
- 禁止凭空增加不存在的模型、数据、验证条件、优化阶段、反馈循环、“智能决策层”或“系统平台层”，也禁止为了美观保留不影响逻辑的重复节点。反馈箭头只有在真实迭代、修正或回传存在时才使用，并采用虚线或其它明确线型标识含义。
- 节点过多时，优先按层级、问题、输入/模型/输出/验证分组，或拆成总体路线图与局部算法图、多面板 Figure；不得通过缩小字体、堆叠节点或增加装饰性框体掩盖结构复杂性。

### 9.3 BrightTech-Info 在流程图中的语义

- 画布使用白色或极浅灰背景；数据、模型、约束、验证、输出等语义层可使用可区分的离散色，并在 `求解/视觉编码表.md` 固化实际取值。BrightTech-Info 仅在不牺牲可读性时提供可选色义。
- 同一语义层或同类节点复用同一颜色；验证门可使用统一强调色；关键节点可用 `Highlight`，但颜色不得成为唯一层级编码，必要时同时使用边框、虚线分组、节点形状、线型、位置和文字标签。
- 节点可适度透明，但文字和边框必须清晰；箭头使用深色或中高对比度颜色，不使用大面积渐变、发光、厚重阴影、纹理、立体按钮或装饰性 3D。渐变只在表达连续状态、连续阶段或连续数值时使用。
- 灰度打印和论文缩放后仍应识别主要层级、箭头方向和验证门；流程图应轻量、清晰、适合版心，不能做成商业海报。

### 9.4 TikZ 结构实现与接入

- 正式流程图必须由 XeLaTeX + TikZ 直接生成矢量 PDF，禁止截图、HTML/ECharts/PowerPoint/Origin/draw.io/软件界面输出、带水印图片和 Markdown ASCII 图。
- 节点以中文为主，数学变量和公式使用 `$...$`；单节点尽量 1--3 行，宽度、字体和内边距按论文版心调整。节点不得重叠，箭头不得穿过节点文字。
- 主文件保留 `\usepackage{tikz}` 以及 `\usetikzlibrary{arrows.meta,positioning,fit,calc,shapes.geometric,shapes.arrows}`。图题由 `\caption{}` 提供，每张图有唯一 `\label{}`，正文先用 `\ref{}` 引用后插入图。
- XeLaTeX 日志不得出现 `Missing character`、`fontspec Error`、字体缺失、节点/版心溢出或关键文字裁切。视觉质量、灰度、缩放和结构门禁必须在图进入论文前完成。

### 9.5 流程图质量门禁

只有下列项目全部通过，流程图状态才可标记为“通过”并进入正式图片目录和论文：

- [ ] 流程图有明确科学用途，且已在 Figure Plan 和 Flowchart Plan 中定义；机理/几何示意图则已在 Figure Plan 和 Schematic Plan 中定义；
- [ ] 类型与真实模型结构匹配，节点和箭头均可追溯到题面、代码、公式、结果或验证；
- [ ] 没有虚构节点、数据、模型、验证条件、反馈、优化阶段或装饰节点；
- [ ] 箭头方向和箭头文字真实，反馈箭头确实对应迭代/修正/回传；
- [ ] 验证门写有真实指标、约束、阈值或检查内容；
- [ ] 节点文字简洁，无重叠，箭头不穿字，布局和拆图决策合理；
- [ ] BrightTech-Info 颜色有语义、跨图一致，颜色不是唯一层级编码，灰度打印可辨；
- [ ] 无截图、水印、软件边框、字体缺失、版心溢出、裁切或缩放不可读；
- [ ] PDF 为 XeLaTeX/TikZ 矢量输出，图题、label、正文引用、结果索引和计划字段一致；
- [ ] 正式输出使用语义化文件名并保存到 `求解/问题X/图片/` 或 `求解/图片/`，必要的 PNG 仅作为视觉检查副本。

任一项失败都标记为“未完成”，不得进入论文；修复后必须重新渲染和审计。

## 10. Figure Plan 字段

`求解/求解计划.md` 和 `求解/视觉计划.json` 中每个 Figure 至少填写并保持一致：

- Figure ID、所属问题、核心科学问题和拟支撑结论；
- 数据源、结果文件、字段和单位、生成脚本/函数及结果索引位置；
- 图型、Panel 数量、每个 Panel 的问题/含义、布局和 `Figure archetype`；
- 是否调用 `academic-figure-skill`、匹配的 `assets/figures/` 目录，以及 `native run / visual adapt / cross-type inherit` 模式；
- Python/R 运行时、输出脚本、PDF/SVG 正式路径、PNG 预览路径、统计报告路径和 QA 报告路径；
- 颜色 token、线型、marker、共享轴/色标和单位；
- 为什么选择该图型、为什么不使用柱状图/饼图/三维图（若相关）；
- 是否与其它 Figure 组合、是否需要二维替代；
- 论文章节、唯一 LaTeX `label`、正文引用和当前质量状态；
- 渲染、字体、重叠、裁切、灰度和论文缩放检查状态。

Evidence Matrix 的每一行还必须登记 `applicability`、`reason`、`data_shape`、`representation`、结构化结果路径和 Figure/Schematic ID。先运行计划阶段审计：

```powershell
python 华为杯_求解规范/tools/audit_visual_plan.py --plan 求解/视觉计划.json --stage plan --project-root . --report 求解/视觉计划.plan.audit.json
```

Figure Plan 未完成或状态不是“通过”时，不得在论文中引用该图。

## 11. 输出目录与命名

- 正式结果图保存到 `求解/问题X/图片/`；中间图和烟雾测试图保存到 `求解/问题X/结果/` 或临时目录，不混入正式目录。
- 文件名使用稳定的语义化格式，例如 `q1_fig01_prediction_diagnostics.png`、`q2_fig02_pareto_front.pdf`；不得使用 `final2_new.png` 等不可追溯名称。
- 同一 Figure 可同时导出 PDF/SVG（矢量）和 PNG（论文/审阅），两者必须来自同一次绘图和同一结果文件。
- 结果索引记录图文件、数据源、代码入口、视觉编码版本、质量状态和论文引用标签。

## 13. 与 LaTeX 论文流程的衔接

论文规范只负责图像路径、宽度、图题、标签、正文引用、PDF 缩放可读性和裁切检查。图像视觉风格、图型选择、颜色、透明度、三维/柱状/饼图限制和 Figure Plan 均以本文件为准。

正式链路为：

```text
真实结果/已审计机理与模型结构 → Figure/Schematic/Flowchart Plan
→ 普通科学结果图：academic-figure-skill（资产优先、实际渲染、统计/QA）
→ 机理/几何示意图：Schematic Plan + TikZ/XeLaTeX
→ 流程图/模型结构图：Flowchart Plan + TikZ/XeLaTeX
→ 渲染/质量检查
→ 求解/问题X/图片/ → LaTeX \includegraphics
→ XeLaTeX PDF → 论文视觉与页数验收
```

在普通图全部渲染后运行 `--stage render`；在论文 TeX 组合完成后运行 `--stage paper --main-tex 论文/论文.tex`，核对计划 label、正式图与正文引用。任一阶段失败都返回上游修复，不能以正文达到 45 页代替视觉门禁。

不得在论文阶段重新生成与求解结果不一致的图片，不得修改官方 `gmcmthesis.cls`、`gmcm-title.sty`、`gmcm.bst` 或 `figures/` 资源来迁就绘图。
