# Mathematical-Modeling Figure Routing

Read this reference for Huawei Cup and other mathematical-modeling papers.
It extends the biological/statistical asset catalog without weakening the
Figure Contract, semantic-color rules, or data-integrity gate.

## Evidence-first portfolio

Review each problem across four evidence roles: mechanism/geometry, main
result, independent validation/error/constraint, and sensitivity/robustness/
scenario. A role may be N/A only with a concrete reason. Multi-point scans,
repeated trials, distributions, error structures, matrices/surfaces, and
spatial geometry are visual-first data shapes.

Use `求解/视觉计划.json` as the machine-readable contract. The computation
module must create every declared result file before rendering. Never invent
demo values in a contest work directory; demo data inside production assets
exists only to preview the visual system.

## Production asset routes

| Scientific need | Asset directory | Typical evidence |
|---|---|---|
| 3D path with inspectable projections | `TrajectoryProjection/` | trajectory, orbit, spatial reconstruction |
| Parameter sweep with boundary/optimum | `ParameterSweep/` | sensitivity, feasible region, theoretical limit |
| Signed residual and invariant checks | `ResidualDiagnostics/` | residual structure, conservation, component error |
| Repeated recovery experiment | `MonteCarloRecovery/` | injection-recovery, bias, coverage, repeatability |
| Convergence and feasibility history | `ConvergenceBand/` | optimizer convergence, multi-seed stability, violation |
| Ranked local sensitivity | `SensitivityTornado/` | parameter influence and uncertainty intervals |
| Scenario/ablation response matrix | `ScenarioHeatmap/` | switch-off tests, scenarios, interactions |
| Signed component contribution | `ContributionWaterfall/` | delay/error/cost/benefit decomposition |
| Phase raster and folded profile | `PhaseProfile/` | periodic signal, sampling, folding, bin design |
| Resource/time design curve | `ResourceDesign/` | observing time, budget, capacity, knee point |

Match by scientific semantics before column names. Use `visual_adapt` when the
asset's data structure and question match; only field mapping, data path, and
incompatible mathematical transforms may change. Use `cross_type_inherit`
when the structure differs. Do not nest a full multi-panel production figure
inside another decorative panel.

## Visual richness without chartjunk

- Across a standard/complex problem, prefer at least two genuinely different
  figure families when the evidence supports them.
- Across a four-question paper, review whether at least two archetypes and
  several layouts are justified; do not repeat equal `1×2` everywhere.
- Use a hero panel for 3--6 panel `asymmetric_mixed` or `schematic_led`
  figures. Keep supporting panels quieter.
- Preserve 2--4 semantic main colors plus one accent per Figure. A paper may
  use a broader stable vocabulary across distinct semantics, but no color may
  be decorative or randomly reassigned.
- Add key thresholds, optimums, boundaries, uncertainty bands, and concise
  direct labels when they make the conclusion self-contained.

## Page-aware evidence portfolio

For a paper with a body-page gate, add a `paper_section` and an approximate
early/middle/late placement to the human Figure Plan. Review the portfolio
before computation and again from a rendered page contact sheet. The goal is
not equal figure counts: it is to keep mechanism, main result, validation,
error, and boundary evidence close to the question they support and to avoid
a visually empty late third.

When the draft is short or sparse, recover evidence in this order:

1. parameter identifiability/uncertainty (objective landscape, profile,
   bootstrap, confidence region);
2. hard-split validation (fold/device/scenario forest plot or heatmap, paired
   performance difference, failure fold annotation);
3. error structure (residual strata, calibration, tail/threshold behavior,
   temporal or spatial drift);
4. model selection and ablation (win/loss map, rank stability, component
   response) only for candidates that were truly run;
5. sensitivity, robustness, counterfactual, feasible boundary, or deployment
   limit derived from real computations.

Prefer a 3--5 panel composite when these views answer one conclusion. Apply
the anti-redundancy audit: a different visual encoding of the same values is
not new evidence. Do not create decorative 3D, synthetic example curves,
generic process icons, or a flowchart for every question. Detailed fold
tables, feature dictionaries, file checks, hashes, and delivery mechanics are
supporting material; visualize only the scientific summary that changes the
reader's conclusion.

Mechanism/geometry schematics use the Huawei Cup Schematic Plan and
TikZ/XeLaTeX. Algorithm, workflow, architecture, or data-flow diagrams use the
Flowchart Plan and TikZ/XeLaTeX. The `schematic_led` archetype only governs
composition after those structural gates pass.
