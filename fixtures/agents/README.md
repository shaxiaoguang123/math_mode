# Agent runtime fixtures

The authoritative examples are generated by actual runtime tests rather than
static invented PASS records:

- `tests/test_agents.py` exercises scoped transport, tampering, actor/question
  attribution, honest human-gate rejection, retry budgets, backend crashes and
  reference-source admission using an explicitly nonreasoning fixture backend.
- `tests/test_orchestrator.py` registers actual original inputs and statistics,
  then checks missing phase prerequisites, cycles and human-event boundaries.
- `tests/test_probes.py` executes the probe implementation, computes all six
  categories and actually admits/rejects fallback execution from pinned triggers.
- `tests/test_upstream.py` computes, independently validates and freezes two
  dependent questions, then observes invalidation after the first is thawed.
- `tests/test_reference_access.py` uses an actual numerical freeze with explicitly
  mocked framer/writer authorship to test immutable blind checkpoint copies and
  access admission. It does not constitute an actual fully authored contest paper.
- `tests/test_recovery.py` starts actual private fixture processes, interrupts their
  owners and children, refuses recovery while recorded descendants remain alive,
  and verifies preserved evidence and continued attempt counts for runner/agent
  transports. It also distinguishes pre-launch interruption from missing PID
  evidence after launch. Only processes created by these tests are terminated.
- `tests/test_workflow.py` consumes `workflow_plan.json`, executes actual probes,
  main/baseline models and independent validation, then tests semantic review and
  freeze gates, pointer-loss adoption and fresh execution after thaw. Role
  provenance alone is explicitly mocked; the unpatched coordinator rejects these
  authored semantic fixtures. Tests also reject concurrent workflow advancement.

`workflow_plan.json` is a structural plan for the synthetic `validation-fixture`
workspace built by the lifecycle tests. It includes no measured values or invented
execution IDs. On an empty workspace it cannot pass the gates. Adapt its case,
paths, questions and claim locators to actual artifacts before real use; the
example does not supply live framing/modeling/semantic reasoning handoffs.

`fallback_decision.json` demonstrates the optional `execution_role=fallback`
decision field and is structural only. Its illustrative references cannot admit
execution. `tests/test_workflow_fallback.py` creates actual main-trigger and
fallback-probe reports, runs a median pairwise-slope solver plus baseline,
independently recomputes their metrics and freezes the selected fallback. The
test doubles only role provenance, preserves rejected main-method assumptions,
and rejects missing/misassigned screening evidence and tampered frozen lineage.

`blocked_schedule.json` is a portable structural example for the `runner-fixture`
workspace created by the tests. It deliberately lacks framed problem/symbol/DAG
contracts and therefore cannot dispatch a council call. It is not an end-to-end
positive benchmark. Create a private fixture workspace and compute `data-audit`
before evaluating the scheduling guard; do not use the public repository as a
competition workspace.

Actual configured Codex backend calls are separately documented in
`docs/audit/t08_agent_runtime_progress.md`. Their raw task/input/response/transcript
evidence stays outside the public template. The successful council handoff and
scheduled framer/resume checks demonstrate transport integration only.
