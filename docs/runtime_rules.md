# MathMode 共享运行规则

本文件是 Codex 与 Claude Code 的共同规则入口。它负责路由和不可跳过的证据
要求；详细规范与机器契约仍各有唯一来源。Git 当前状态、实际文件和新检查
优先于旧审计中的仓库状态描述。

## 权威与原始资产

用户要求优先；其次依次为题面硬约束、附件及官方提交要求、求解规范、绘图
规范、论文规范与工具接口。项目经验不能冒充赛事规则。`competition_policy.json`
中的官方来源、当届模板哈希、封面/匿名范围、目录、届次和页数限制必须核验。
45 页只是历史经验提醒，不能阻断完整的短论文，也不能成为注水理由。

正式比赛使用 `mathmode init` 建立仓库外的工作区，输入角色由用户/host 明确
声明。不得回写原始附件；压缩包先核对目录和规模，只处理副本。自主采集数据
须保留来源、日期、许可、采集/整理脚本和原始快照。公开模板库不接收正式私有数据。
参考论文数字、示例图和验收演练不构成当前赛题证据。

保留原 DOCX、class/sty、题头宏、署名、图片和两个完整 academic-figure-skill
镜像。`gmcm-title.sty` 是现有题头视觉实现唯一来源；使用
`\GMCMContestTitle{届次中文数字}`，从 policy 取得届次。未经明确要求不得改变
该组件参数。官方渲染使用 XeLaTeX 和 STXinwei，缺字体报错，不暗中替换。

## 求解与模型决策

详细规则：`华为杯_求解规范/华为杯_求解规范.md`。
先审计实际解释器和依赖，不重复安装大型环境。当前开发可使用用户已授权的
Conda `test`。建模前完整读取题面、数据和附件说明，记录每问输入/输出、指标、
单位、边界、精度、资源、数据切分、依赖和 AI 要求。审计缺失、重复、异常、
时间/空间/分组范围与泄漏，不在数据审计阶段擅自选择最终模型。

逐问定义可完成相同任务的 baseline 和 main，至多一个有明确触发条件的 fallback。
从机理/经典方法开始，复杂性须有依据。正式编码前执行低成本风险探针，覆盖
可执行性、数据覆盖、假设、退化、扰动和规模。决策使用新鲜实测证据；autopilot
如实记录 agent，human_gate 等待真实 host 用户事件。不得把模型生成文本冒充人工决定。

`human_gate` 由调度器准备包含题意、模型卡和实测探针的请求，再通过交互终端
`human-decision` 接收选择、理由和明确提交；取消或暂缓不发布模型选择。等待期间
证据变化须重新请求，恢复时核验事件并复用已接收的决定。终端输入不是人员身份
认证，测试替身不构成真实人工验收。人工选择仍不能跳过数值、独立审查与冻结门禁。

代码采用独立入口、固定种子、完整依赖与真实过程记录；计算和绘图分离。
独立验证者依据原始输入与最终输出重算指标、约束和基线比较，不导入求解源码
或中间结果。结构通过不是科学通过；假设、模型适用性、单位和结论边界需要
独立语义审查。真实 warning 必须处理，不能把手写 QA PASS 当证据。
检查角色可读取原始 WARN/FAIL 报告；继续建模需要覆盖每条警告和限制的处理提案，
并由不同于提案作者、原审查者和被审查作者的角色独立复核。错误和要求修复的
事项仍阻断。获准保留的限制以 `LIMITED` 进入阶段门禁及冻结记录，自动继承到
实际依赖上游冻结的后续问题；原报告不改为 PASS。详见 `docs/workflow_v2.md`。
选中模型使用的假设在 G5 前须有独立审查的 `assumption_plan` 和当前实测报告。
参数/种子扰动须预先声明，使用同一生产模型代码和固定原始输入，由独立验证器
重算指标后比较变化量。不适用须给出具体理由；不得将账本中手写的 `tested`
当作实验结果。冻结绑定该报告，变化后使下游过期。

同一未解决原因最多三次总尝试，保留失败证据和实际修复，不能换 ID 重置预算。
输入/代码/参数变化使下游过期。冻结后禁止局部改数字；显式解冻后重新求解与
验证，保留旧版本。不同问题按 DAG 依赖推进，下游只能消费当前有效的上游冻结值。

盲测模式用于独立建模评估，多问赛题须先逐问冻结模型、代码、结果和论文草稿，
再用 `seal-case-baseline` 绑定全部问题，之后才能读取同题资料。任何同题读取
都会阻止新增盲测检查点，不能换一问恢复盲测声明。非盲测工作可在初始化时显式
选择 `--no-blind-reference-mode`；运行途中不能修改模式。宿主外的既往阅读不可验证。

## 视觉、论文和支撑材料

绘图唯一详细来源：`华为杯_求解规范/华为杯_绘图规范.md`。建视觉计划前完整
读取；每次绘图前再次读取。生成/审查机理图或流程图时也再次读取论文章节规范。
先建立 Evidence Matrix 与 Figure/Schematic/Flowchart Plan；普通结果图必须使用
运行时对应的完整 academic-figure-skill，默认中文文字，并通过实际中文字体与
反乱码门禁。两个镜像均须保留全部 scripts、references 和 assets，不用精简版替代。

普通结果图只读取真实最终结果；统计、误差、比较、敏感性和稳健性实验均须
真实运行。机理图和流程图保持项目 TikZ/XeLaTeX 路线，节点、箭头、反馈、
分支和图型应对应真实模型。检查字体、warning、重叠、裁切、灰度、缩放、图题、
label 和正文引用；图表支撑具体结论，不按数量复制同一结果。

论文唯一详细来源：`华为杯_论文规范模板/华为杯_论文章节规范.md` 和同目录
`README.md`。写作前完整读取，并读取 `agent_manifest.schema.json`、章节页数
基线和 `page_targets.json`。正式章节源使用 `.tex`；Markdown 仅用于工作记录和
legacy archive。不得以 `example.tex` 当生产论文，不得倒灌 Word 修改覆盖 TeX。

每个正文一级章必须回答科学问题或提供不可替代的模型/证据；模型推导、主结果、
验证、误差、对比和边界应与对应问题相邻。全量逐折表、哈希、文件清单和构建
记录进入附录、结果索引或支撑材料，不能在末尾堆“完整性”章节凑页数。
禁止空白页、无意义分页、重复结论、虚构实验、无关背景和放大格式凑页数。

最终链路：真实结果/冻结值 → 结果索引及论文输入 → TeX → 视觉计划 paper
审计 → audit_tex → XeLaTeX 双遍 → audit_paper → PDF 渲染检查。最终 PDF
检查匿名、引用、公式/图表边界、字体、未定义引用和横向溢出；检查正文后段
连续稀疏页。章节检测若因同页标题或中文 CMap 不可靠，用 heading JSON、渲染
和 OCR/视觉证据交叉确认。Word/DOCX 仅按用户或官方要求从同源派生并审计。

问题数量确定后初始化支撑材料清单；逐问登记唯一入口、完整源码、运行记录、
自主数据溯源和补充图表。支撑包是可重建快照，不在快照里单独修复代码/数据。
每问完成后构建并运行 question 审计，最终运行 final 审计；正文/清单/官方输出
变化后重建。README 列出文件作用，构建清单、SHA-256、源码和快照一致，无未登记文件。

## 完成与恢复

题目全部求解，代码实跑、独立验证、结果索引、AI 使用记录、真实图表、冻结
数字、论文、官方附件和支撑包均新鲜且一致后，才能进入最终审计。论文通过
当届官方 policy 与视觉门禁、XeLaTeX 双遍和可读 PDF 检查后才可称最终合规。
门禁缺失时给出精确原因、已完成阶段、真实尝试、现存产物和最小解决条件。

`docs/workflow_v2.md` 描述 G0–G8；`docs/contracts.md` 描述可执行契约与局限。
阶段实现状态以 `docs/audit/` 和真实测试为准，不能把设计文档当作已实现能力。
开发按 `git_rule.md` 分阶段检查、提交和推送；最终 PR/CI PASS 后 READY FOR REVIEW，
未经用户明确要求不合并、不执行比赛外部提交。
